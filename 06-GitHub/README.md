## 🔗 About GitHub

GitHub is a web-based platform built around Git version control.

It provides tools for:

- Hosting and managing repositories
- Tracking changes and commit history
- Collaborating through branches and pull requests
- Reporting tasks and bugs using issues
- Reviewing and discussing code changes
- Creating project documentation using Markdown
- Automating development workflows using GitHub Actions

**Git vs GitHub:** Git manages version history, while GitHub hosts Git repositories and provides collaboration features.

## 🧩 Key Concepts

### 1. GitHub Repository

A repository stores project files and their Git version history.

Repositories can be:

- **Public:** Accessible to everyone.
- **Private:** Accessible only to authorized users.

### 2. Commits and History

Commits record project changes.

GitHub provides a visual interface to inspect commit messages, authors, timestamps, and file modifications.

### 3. Branches

Branches allow developers to work on features or fixes independently.

Changes can later be proposed for integration into another branch.

### 4. Pull Requests

A pull request proposes changes from one branch to another.

Pull requests support:

- Reviewing changes
- Discussing improvements
- Checking automated test results
- Approving or requesting modifications
- Merging changes

### 5. GitHub Issues

Issues help teams track bugs, tasks, feature requests, and discussions.

Issues can include labels, assignees, milestones, and references to pull requests.

### 6. Markdown Documentation

GitHub supports Markdown for documentation.

Common Markdown elements include:

- Headings and paragraphs
- Bold and italic text
- Lists and tables
- Code blocks
- Hyperlinks and images
- Task lists

### 7. GitHub Actions

GitHub Actions supports workflow automation, including testing, building, and deploying software.

Workflows are commonly defined using YAML files inside `.github/workflows/`.

## 💻 Practical Implementation

### 1. Create a Repository

1. Sign in to [GitHub](https://github.com/).
2. Click **New repository**.
3. Enter a repository name.
4. Select Public or Private visibility.
5. Optionally initialize with a README.
6. Click **Create repository**.

### 2. Upload Project Files

1. Open the repository.
2. Select **Add file → Upload files**.
3. Choose the required files.
4. Enter a meaningful commit message.
5. Commit the changes.

### 3. Explore Commit History

Open the repository's commit history to inspect previous revisions.

Review commit messages, timestamps, and changed files.

### 4. Create a Branch

1. Open the repository.
2. Select the branch dropdown.
3. Enter a new branch name.
4. Choose the option to create the branch.

### 5. Create a Pull Request

1. Make and commit a change on the new branch.
2. Open the **Pull requests** tab.
3. Select **New pull request**.
4. Choose the base and compare branches.
5. Review the changes.
6. Add a title and description.
7. Submit the pull request.

### 6. Create an Issue

1. Open the **Issues** tab.
2. Click **New issue**.
3. Enter a descriptive title.
4. Add a clear description.
5. Submit the issue.

### 7. Document Using Markdown

Create or edit `README.md`.

Include:

- Project overview
- Objectives
- Folder structure
- Setup instructions
- Practical examples
- References and author details

Preview the rendered Markdown on GitHub.
