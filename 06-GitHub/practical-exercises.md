
# 💻 GitHub — Practical Exercises

### Technical Writing Laboratory | MNIT Jaipur

> **Create repositories. Manage changes. Collaborate effectively.**

This practical demonstrates essential GitHub operations using a web browser and a GitHub account.

---

## 🎯 Objectives

- Create and configure a GitHub repository.
- Upload and organize project files.
- Explore commit history.
- Create and manage branches.
- Submit a pull request.
- Create and track an issue.
- Preview Markdown documentation.

---

## 🛠️ Prerequisites

- GitHub account
- Web browser
- Internet connection
- Basic understanding of Git
- Markdown file for documentation

---

## 🔥 Exercise 1 — Create a Repository

**Aim:** Create a new repository on GitHub.

### Procedure

1. Sign in to GitHub.
2. Click **New repository**.
3. Enter the repository name `github-practice`.
4. Select Public or Private.
5. Enable **Add a README file**.
6. Click **Create repository**.

### Expected Result

A new GitHub repository is created with a `README.md` file.

**Screenshot:** `01-repository-overview.png`

---

## 🔥 Exercise 2 — Upload and Commit Files

**Aim:** Demonstrate file management using GitHub.

### Procedure

1. Open the repository.
2. Click **Add file → Create new file**.
3. Enter the filename `notes.md`.
4. Add the following content:

```markdown
# GitHub Practice Notes

This file demonstrates repository file management.

## Features

- Commits
- Branches
- Pull requests
- Issues
```

5. Enter the commit message:

```text
Add GitHub practice notes
```

6. Commit the changes to the default branch.

### Expected Result

The new Markdown file appears in the repository.

## 🔥 Exercise 3 — View Commit History

**Aim:** Inspect repository revisions.

### Procedure

1. Open the repository's **Code** tab.
2. Open its commit history.
3. Select a commit.
4. Review the commit message and changed files.

### Expected Result

GitHub displays the recorded commits and their associated changes.

**Screenshot:** `02-commit-history.png`

## 🔥 Exercise 4 — Create a Branch

**Aim:** Demonstrate independent development.

### Procedure

1. Open the repository.
2. Click the branch selector.
3. Enter:

```text
feature-readme
```

4. Create the branch from the default branch.
5. Verify that `feature-readme` is selected.

### Expected Result

A new branch named `feature-readme` is created.

**Screenshot:** `03-branches.png`

---

## 🔥 Exercise 5 — Create a Pull Request

**Aim:** Propose and review changes.

### Procedure

1. Switch to `feature-readme`.
2. Open `README.md`.
3. Click **Edit**.
4. Add:

```markdown
## Project Objectives

- Learn GitHub repository management.
- Understand branches and pull requests.
- Practice collaborative documentation.
```

5. Commit the changes to `feature-readme`.
6. Open **Pull requests → New pull request**.
7. Select the default branch as the base and `feature-readme` as the compare branch.
8. Review the changes.
9. Enter the title:

```text
Improve README documentation
```

10. Add a description explaining the update.
11. Click **Create pull request**.

### Expected Result

A pull request is created, displaying the proposed README changes.

**Screenshot:** `04-pull-request.png`

### Optional: Merge the Pull Request

If the changes are correct and merging is permitted:

1. Open the pull request.
2. Click **Merge pull request**.
3. Confirm the merge.

## 🔥 Exercise 6 — Create a GitHub Issue

**Aim:** Demonstrate issue tracking.

### Procedure

1. Open the repository's **Issues** tab.
2. Click **New issue**.
3. Enter the title:

```text
Improve repository documentation
```

4. Enter the description:

```text
Review the README and add clearer navigation,
setup instructions, and practical examples.
```

5. Submit the issue.

### Expected Result

The issue appears in the repository's issue tracker.

**Screenshot:** `05-issues.png`

**Aim:** Demonstrate GitHub Markdown rendering.

### Procedure

1. Open `README.md`.

3. Open `notes.md`.
4. Verify the Markdown formatting.

## 🔎 Practical Observations

- GitHub repositories organize project files and version history.
- Commits record changes made to project files.
- Branches isolate modifications.
- Pull requests support change review.
- Issues help track project tasks.
- Markdown provides structured project documentation.
